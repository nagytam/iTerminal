### `iConsole` — reusable terminal UI framework
General-purpose TUI infrastructure with no knowledge of file managers. Key subsystems:

- **Controls** (`iConsole/Controls/`): `Window` is the base for all interactive UI panels. Controls handle `HandleKeyEventAsync` and render into a buffer.
- **Commands** (`iConsole/Commands/Command.cs`): User actions. Override `Key`, optionally `CanExecute()`, and `ExecuteAsync(object? args)`. Commands are attached to controls and dispatched by the key router. `Command.RunAsync` wraps execution with `CanExecute` gating, exception capture, and `ICommandLogger` recording — dispatch through it, not `ExecuteAsync` directly.
- **Jobs** (`iConsole/Jobs/Job.cs`): Long-running background loops (rendering, keyboard polling, network info). Each `Job` subclass implements `RunIterationAsync`. Jobs are registered as `IJob` singletons and run on the `Desktop` lifecycle, not the `TaskManager`.
- **TaskManager** (`iConsole/Tasks/TaskManager.cs`): Priority queue (`Rendering=0 > Input=1 > Background=2`) with multiple worker threads. Used for one-shot async work (directory enumeration, file copy). `BackgroundTask` is the base; override `ExecuteAsync()` and `Priority`.
- **Data types** (`iConsole/Data/`): `Url`, `Container` (URL scheme constants), `KeyEvent`, `Position`, `Size`, `ConcurrentObservableCollection<T>` (thread-safe, `ReplaceAll` for atomic batch swaps), `ConxelString` (styled character strings for rendering).
- **Services** (`iConsole/Services/`): `IDateTimeProviderService` (cached `DateTime.Now`), `IFrequentExecutionGuardService` (throttles `PropertyChanged` to max ~20/s), `IStopwatchFactory`/`IStopwatch` (injectable timing), `IThemeService`, `IErrorPromptService`.
- **Notifications** (`iConsole/Services/INotificationService.cs`, `Jobs/NotificationJob.cs`, `Controls/Toast.cs`, `Controls/ToastHost.cs`): self-dismissing toasts posted from any thread — see "Notifications and toasts" below.
- **Diagnostics** (`iConsole/Diagnostics/`): `ICommandLogger`/`IScreenLogger` capture command executions and rendered screen snapshots for agentic/behavioural tests. `AddiConsoleCore` registers the `Null*` no-op implementations by default; `iConsole.Test.Core` provides `InMemoryCommandLogger`/`InMemoryScreenLogger`, and `AppHarness` wires those in so tests can assert on what ran and what was drawn.

### Notifications and toasts (`INotificationService`, `NotificationJob`, `ToastHost`)
A notification is a short message the app shows without stopping the user: a title, an optional message and a severity (`Info`, `Success`, `Warning`, `Error`). Any code posts one with `INotificationService.Notify` — from any thread, returning at once — and it appears as a `Toast` in the top right corner, over panels, dialogs and menus alike, then leaves by itself (4 s; a warning 6 s, an error 10 s; `Timeout.InfiniteTimeSpan` stays until dismissed). A click dismisses it. It never takes focus or a key.

- **Three parts, and only the first is needed to post.** `NotificationService` (iConsole, singleton) holds the lists: at most `MaxVisible` (4) on screen, the rest waiting their turn with their time not yet started, and a capped `History`. `NotificationJob` is the clock: every 100 ms it hands the service the time that passed (`Advance`). `ToastHost`, a control on the screen's root, draws `Active`. `AddiConsoleCore` registers all three; a screen only has to add the host (`TerminalScreen` takes it as an optional constructor argument).
- **Time is handed to the service, not read by it** — which is what lets the job stop it while the terminal is lent to a shell (`ConsoleOwnership.IsLent`): a "copy finished" that expired behind Ctrl+O would never have been seen. It is also what makes the service testable without a clock. The first `Toast` counted `OnIdle` calls instead, and an idle pass is not a length of time: a thousand a second on a quiet screen, none while a dialog repaints.
- **`ToastHost` synchronises from `OnIdle`, by polling `INotificationService.Version`.** Notifications are posted from task workers, and attaching a control there would race the renderer walking the tree — the same reason `ProgressWindow` closes itself from `OnIdle`. It must do nothing when the version has not moved: touching the tree moves `Control.TreeVersion`, and a host that did so on every idle pass would have the screen repainted from scratch for as long as a toast was up.
- **Each toast is a control of its own, attached and removed.** A layer is never cleared between frames, so one rectangle that merely drew fewer rows would leave the expired toast on screen; attaching and removing is what triggers the repaint from scratch.
- **The stack sits one layer above everything else on screen, worked out rather than fixed** (`ToastHost.ApplyZOrder`: the highest Z-order among the host's visible siblings, plus one, re-checked on every idle pass while a toast is up). A fixed high Z-order would cost a buffer layer for every number below it; and a dialog can open over the panels while a toast is showing.
- **A click reaches a toast only because `TerminalScreen.HandleMouseEventAsync` offers it to the host first**: the base implementation offers a click to the children in the order they were added, and the panel under the toast would take it. With a dialog open the mouse goes to the dialog, so a toast is not clickable then — it still expires.
- **Toasts use no frame characters.** `AssertNoStrayFrames` in the end-to-end suite reads any `╔╗╚╝║` outside the panels as the ghost of a closed window.
- **Every operation with a progress window announces how it ended** (`TaskNotificationHelper.NotifyWhenFinished`, armed by `ProgressWindowFactory.Create`): copy, move, delete, compress, extract and their batches — success, cancelled (warning) or failed (error, with `BackgroundTask.Error`). The window is gone the moment the task succeeds, or earlier when the user closed it to get on with something else, which is the case a notification is for. It checks the status when armed as well as subscribing: a small local copy is over before the window is built. The text comes from the task's `Description` (a heading, what it was done to, and a last line saying how it ended — or one sentence that says everything) and from `BackgroundTask.Subject`, the few-word form ("readme.txt to target") a task sets because two whole paths do not fit a toast. A new task meant for a progress window should set `Subject`.
- **Post a notification for what finishes behind the user's back, not for what they are looking at.** A dialog's own footer or the panel's footer is still the place for the result of a key just pressed there.

### Small input and navigation controls
- **`SegmentedControl`**: one-row pick-one (` Day  Week  Month `). Left/Right/Home/End, wheel and click on an option; `IndexAtColumn` maps a click to an option. Use it where a `RadioGroup` would waste rows.
- **`Breadcrumb`**: a clickable trail (`Home › Docs › App`). `Breadcrumb.Layout` folds the middle into `…` when the trail is wider than the control, keeping the first and last segments. Left/Right move the highlight, Enter or a click raises `SegmentActivated(index)`.
- **`Expander`**: a collapsible section with a `▶`/`▼` header. `Content` is attached with `AddControl` only while expanded (and detached when collapsed), so hidden children never draw or take keys; `ViewSize.Height` follows (`1` or `1 + ContentHeight`).
- **`Pagination`**: `‹ Page 3 of 12 ›` for paged results. `TotalItems` and `PageSize` give `PageCount` (an empty list has one page); `Page` is clamped and raises `PageChanged`, `FirstItemIndex` is the offset to load. Arrows, PageUp/PageDown, Home/End, the wheel and a click on either arrow change the page.
- **`Rating`**: `★★★☆☆`, `Maximum` stars. Left/Right, digit keys or a click set `Value`; clicking the current star clears it.
- **`TextBox` click**: a click in the well takes focus and puts the cursor under the pointer (past the end it lands on the end).
- **`TreeView` mouse**: a click focuses a row; a click on the glyph, or a second click on the focused row, toggles the node; the wheel scrolls three rows.
- **`LinkLabel`**: frameless hyperlink-style text; Enter, Space or a click raise `Activated` (the host decides what it does; `Target` carries what it points at). Width follows `Text`.
- **`Chips`**: removable tags `[rock ×] [jazz ×] [+]` for multi-value fields. `Add` ignores blanks and case-insensitive duplicates; Delete/Backspace or a click on × removes; Enter or a click on `[+]` raises `AddRequested`. `Visible(width)` slides the window so the highlighted chip stays on screen.
- **`ScrollBar` mouse**: the arrows step the cursor one cell, a click on the track jumps to the matching position (`ScrollBar.CursorForClick`, the inverse of where the thumb is drawn), the wheel moves three. Works for both orientations on the bound `ScrollableModel`.
- **`KeyValueList`**: read-only `Key   value` rows with the values lined up (key column = longest key, capped at `MaxKeyWidth`; values cut to fit). `SetItems` resizes the control to one row per pair.
- **`CheckList`**: scrolling `[x] item` list for picking any number of options. Up/Down/PageUp/PageDown/Home/End move, Space toggles the cursor row, `*` inverts all, Enter raises `Activated`; a click moves the cursor and toggles, the wheel moves three rows. `CheckedItems` is the result; `IsReadOnly` blocks toggling.
- **`HexViewer` / `TextViewerControl`**: both now blank the rows past the end of the data (a shorter file used to leave the previous one's rows on screen, since a layer is never cleared). `HexViewer` takes clicks on rows and the wheel; `TextViewerControl` scrolls three rows per wheel notch.
- **`Accordion`**: stacked `Expander` sections with at most one open. `AddSection(header, content, contentHeight)` appends one; opening a section closes the others and the sections re-flow (`Open(index)` / `Open(-1)` drive it from code); `ViewSize.Height` follows the total.
- **`Timeline`**: read-only vertical history, `● 10:02  Build` joined by `│` connectors; the dot takes the `BadgeKind` colour. Shows the newest events when they do not all fit (`FirstVisibleEvent`).
- **`SearchBox.Submitted`**: raised with the text on Enter. Enter is consumed only while someone listens, so a dialog's default button still gets it otherwise.
- **`Calendar`**: 20×8 month grid for picking a date (`FirstDayOfWeek`, `Culture`). The selected day and today live in an `ICalendarModel` (`Today`, `SelectedDate`, `Select`, `Changed`): the control keeps its own by default, and a host that already has such state assigns it to `Model` so grid and host share one selection (the control redraws on `Changed`; `SelectedDateChanged` fires for either side's change). Arrows move a day/week, PageUp/PageDown a month (clamped to the shorter month), Home/End the first/last day, Enter raises `DateActivated`; a click selects a day or steps the month via the header arrows, the wheel steps months. Options: `ShowWeekNumbers` (ISO week column, widens the control to 23), `ShowAdjacentDays` (off leaves the neighbouring months' cells blank and unclickable), `AlwaysEmphasizeSelection` (focused colours without focus, for a host that handles the keys itself). `GridStart` is the pure layout helper. `CalendarDialog` uses it: its `CalendarModel` implements `ICalendarModel`, the dialog keeps the keyboard (meeting entry needs every key, so the grid is `CanFocus = false`) and the grid takes clicks.
- **`Separator.Title`**: sets a heading into a horizontal rule (`⎯⎯ Advanced ⎯⎯⎯⎯`) to divide a form into named groups without a `GroupBox`; `Separator.BuildRule` builds the text.
- **`Meter.ShowPercent`**: overlays the value as ` 42% ` centred on the bar (skipped when the bar is under 6 cells).
- **`TimePicker`**: `[14:05]` / `[14:05:30]` (`ShowSeconds`) time-of-day field, `Value` is a `TimeOnly`. Left/Right pick the field, Up/Down/wheel step it (wrapping within the field, PageUp/PageDown by 10), digits type a value (two digits, then the next field), a click picks a field.
- **`ColorPicker`**: 4×4 grid of the sixteen console colours as swatches; arrows move the cursor (brackets), Enter/Space or a click pick (✓ marks `SelectedColor`).
- **`ComboBox` type-ahead**: with the list closed, a printable key jumps to the next item whose text starts with it (wrapping); Home/End select the first/last item.
- **`Skeleton`**: loading placeholder — grey bars (the last line shorter) with a lighter band sweeping across, advanced from `OnIdle` by the injected `IDateTimeProviderService` (like `Spinner`, time gates the sweep, not idle-pass count). Set `IsActive = false` to blank it when the data lands.
- **`Countdown`**: `MM:SS` (or `H:MM:SS`) until `Target`, counting down on the injected clock; `Start(duration)` / `Stop()`, raises `Finished` once. Redraws only when the displayed text changes; yellow under 10 s, red at zero, `--:--` while idle.
- **`Alert.IsDismissible`**: draws a `×` in the last column; a click on it, or Esc while the alert has focus, clears the message and raises `Dismissed`. Off by default, so existing alerts keep their width and are not focusable.
- **`StepIndicator.StepClicked`**: raised with the index when a step glyph is clicked; the host decides whether that step may be jumped to and sets `Current`.
- **`StrengthMeter`**: one-row password rating `▰▰▰▱ Good` (`PasswordStrength` None/Weak/Fair/Good/Strong, colour by level). Set `Password` as it changes; only the rating is kept, never the text. `StrengthMeter.Rate` is the pure rule of thumb: length steps at 8/12/16, a mix of three or four character classes, and a veto (Weak) for repeats, runs and the usual suspects.
- **`ListBox` type-ahead**: opt in with `EnableTypeAhead`; typed letters move the cursor to the next row starting with them (leading markers like `● ` are ignored; a repeated letter cycles, letters typed within `TypeAheadTimeout` extend the prefix). Off by default because lists in dialogs share the letter keys with the dialog's hot keys.
- **`StatusDot`**: inline state marker `● Connected`; the dot takes the `BadgeKind` colour, the text the normal foreground. Lighter than `Badge` (no filled background), so it fits a list row or a sentence-sized line. `NaturalWidth` is the cells it needs.
- **`ElapsedClock`**: running time `MM:SS` / `H:MM:SS` between `Start()` and `Stop()`, adding up across restarts until `Reset()`; Space toggles and R resets while focused. Uses the injected clock and redraws only when the shown text changes. (Not called `Stopwatch`: that name collides with `System.Diagnostics.Stopwatch` in every file that uses both namespaces.)
- **`TextViewerControl` / `TextEditorControl` mouse**: a click in the text moves the cursor row; in an editor (cursor enabled) it also places the caret in the column, clamped to the end of the line. The scroll bars keep their own clicks. Below the last line selects the last line.
- **`Toolbar`**: one-row action strip `Open F3  Save  Close` of `ToolbarItem(Text, Hint, IsEnabled)`. Left/Right/Home/End move over the enabled items, Enter/Space or a click raise `ItemInvoked(index)`.
- **`Table<T>` sorting**: a click on a header cell raises `SortRequested(column)`; the host sorts its rows and sets `SortColumn` / `SortDescending`, which draw ▲/▼ in that header.
- **`TextBox.Placeholder`**: greyed hint drawn in the well while the box is empty; never part of `Text`.
- **`Table<T>` mouse support**: a click on a body row moves the cursor (a second click on the cursor row raises `RowActivated`), the wheel moves it by three rows, the header row ignores clicks — the same behaviour as `ListBox`.

### Rendering pipeline
Two `JobPriority.Rendering` jobs run continuously and are deliberately decoupled — nothing renders synchronously from a key handler:

1. `ControlRendererJob` walks each `Screen`, collects controls whose `HasStateChanged` is set, renders them into per-Z-order `BufferLayer`s, then `Buffer.Merge()`s them into `MergedLayer` (only when something actually rendered — merging blank new layers would blank the screen).
2. `ConsoleBufferRendererJob` diffs `MergedLayer` against `LastBuffer` line by line (SIMD byte compare), batches runs of changed cells into single `IConsoleDriver.Write` calls, and detects terminal resizes. Both jobs force a full redraw every second as a safety net.

Set the `ITERMINAL_RENDER_DUMPS` environment variable to dump up to 100 frames (buffer contents, render steps, and a reconstructed "what the console actually received" snapshot) to `%TEMP%/iTerminal/renderer-dumps` — the fastest way to debug a visual glitch.

`Buffer.SyncLock` guards the layer array; take it around any resize or merge.

### Lending the terminal to a child process (`ConsoleOwnership`, Ctrl+O)
Ctrl+O hands the *whole* terminal to an interactive shell and takes it back when the shell exits — prompt, line editing, colours, `vim`, `top`, Ctrl+C, all the child's. The app's own terminal panel (now Ctrl+Shift+O, the "command log") cannot be that: it runs one command at a time with its output captured.

- **`ConsoleOwnership` (iConsole, singleton) is the app's claim on the terminal.** The loops that touch it — `ConsoleBufferRendererJob` (writes) and the input readers (`MouseEventPublisherJob`, `PosixTerminalInputPublisherJob`, the polling `KeyboardEventPublisherJob`) — bracket each pass with `TryBeginUse`/`EndUse` and skip the pass when refused. `LendAsync` refuses new passes, waits for the ones under way (a frame, or one 50 ms input wait), then calls every `IConsoleHandoverParticipant`'s `OnConsoleReleased`, runs the borrower on a thread of its own, and calls `OnConsoleReacquired` in reverse — also when the borrower throws. Lends are serialised. A new loop that writes to or reads from the real terminal must take part, or it will draw over the shell or steal its keys.
- **Each participant undoes exactly what it did.** The drivers (every `IConsoleDriver` is a participant; the defaults do nothing) reset colours, clear and show the cursor, and on return put back the colours they believe are set, re-enable VT processing on Windows (the child may switch it off) and clear. The Windows reader gives the console its *original* input mode back (captured before it turned mouse input on and quick edit off) and on return re-applies its own and `FlushConsoleInputBuffer`s — the Enter that ended `exit` is still releasing. The Linux reader leaves raw mode, mouse reporting and non-blocking stdin, and re-enters them (`TCSAFLUSH` drops what was typed). The renderer marks every cell of `LastBuffer` unknown so the next pass repaints the whole screen: a diff against the frame from before the shell would leave the shell's text wherever the panels happened to match.
- **Ctrl+C, Ctrl+\ and Ctrl+Z belong to the child** (`ConsoleInterruptShield`). They reach every process on the console or in the foreground group — the app too, and the generic host's console lifetime stops the app on Ctrl+C. Handlers cannot prevent that (all of them run, the host's among them), so the signal is ignored at the OS level: `SetConsoleCtrlHandler(NULL, TRUE)` on Windows, `sigaction(SIG_IGN)` on Linux with the runtime's own handler saved opaquely and put back (`signal()` would reinstall an `SA_SIGINFO` handler with the wrong calling convention). It is raised only *after* the child has started — an ignored Ctrl+C is inherited.
- **Where the shell runs is the panel's to say** (`IShellLaunchSource.GetShellLaunch`): a local folder starts the user's shell there (the `Shell` setting; else `pwsh` on PATH, else `%ComSpec%`, on Windows — Windows PowerShell 5 is too slow to start for a key that should feel instant — and `$SHELL` elsewhere); the git drive uses the repository's working tree and the archive drive the archive's folder; docker is `docker exec -it -w <folder> <c>` with bash if the image has it and sh if not; ssh is the system's `ssh -t user@host "cd '<folder>' && exec $SHELL -l"`, so it authenticates the way the user's ssh does, not with the drive's saved credentials. Any other panel gets a local shell in the home folder.
- **`InteractiveShellService` adds what a person needs around the handover**: a line saying where the shell runs and that `exit` returns, and — when the program cannot start, or fails within `QuickExit` (no Docker, a stopped container, a refused login) — its message and "Press Enter", since the repaint would otherwise wipe it unread. `InteractiveShellCommand` only *starts* the session (the key handler returns at once) and refreshes every panel once it is over: only the local drive notices its own changes. The end-to-end suite replaces the service with `SandboxServices.Shell`, which borrows the terminal through the real `ConsoleOwnership` and writes onto the virtual screen — so the renderer standing still, and repainting everything afterwards, are what the test sees.

### Platform input plug-ins — `iConsole.Inputs.Posix` / `iConsole.Inputs.Windows`
Each supplies an `ITerminalInputSource` + input-consumer `IJob` and a DI extension called from `Program.cs`: `AddLinuxTerminalInput()` (Linux, ANSI/SGR mouse + raw stdin) and `AddInputWindowsAsync()` (Windows). The Windows path is feature-gated by `WindowsConsoleDriver` (via `Microsoft.FeatureManagement`, config in `appSettings.json`); when off — and on all non-Windows/non-driver paths — it falls back to `AddPollingConsoleKeyboard()`.
