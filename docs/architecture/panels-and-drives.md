### `iTerminal.Core` — file-manager and terminal behavior
Built on top of `iConsole`. Key subsystems:

- **Content models** (`iTerminal.Core/Model/ContentModels/`): Implement `IContentModel` (extends `IScrollableModel` + `IFileSystem`). `ContentModelBase` holds `Entries` (`ConcurrentObservableCollection<IEntry>`), `FilteredEntries` (cached snapshot), cursor/scroll state, and `Update()` (notifies UI after state change). One implementation per drive kind — see the URL-scheme table below.
- **ContentModelService** (`iTerminal.Core/Services/ContentModelService.cs`): Owns the left/right panel models (`"LeftPanel"`/`"RightPanel"`), tracks focus, remembers per-URL cursor positions, and swaps the model instance when a navigation crosses drive kinds.
- **File panel controls** (`iTerminal.Core/Controls/Contents/`): `FilePanel` → `ContentPanel` → `Window`. `ContentBrowser` renders the entry list; `ItemInformation` shows file counts and metadata.
- **Tasks** (`iTerminal.Core/Tasks/`): `FilePanelRefreshTask` enumerates a directory (memory cache → SQLite `FolderContentsCache` → filesystem), streams results in 50-item batches, and runs prefetch for neighbouring folders at `Background` priority. `FileInformationRefreshTask` counts files recursively. Copy/move/delete run as pipelines (`FolderCopyPipeline`, `FolderDeletePipeline`) fed by discovery tasks.
- **Services** (`iTerminal.Core/Services/`): `SettingsService` is SQLite-backed (key/value via EF Core, `iTerminalDbContext`); a no-arg constructor creates a temporary in-memory DB for tests. `MemoryCacheService` wraps `IMemoryCache` with a 5-second default TTL (overridden to 5 minutes for prefetch). `IVaultService` stores remote credentials and `INetworkProfileService` stores host profiles — SSH/SMB models resolve credentials through those, never from the URL alone. Feature services back the dialogs below and are async by contract (never touch the render thread): `IGitService`, `IDotnetSolutionService` (`dotnet build/test/run`), `IPackageManagerService` (WinGet on Windows / Apt on Linux, chosen at registration), `WeatherService`, and `IChatClient`/`IAiChatService`. Every provider is one OpenAI-compatible endpoint behind `AiChatClientFactory` (Microsoft.Extensions.AI's OpenAI adapter, Ollama included through its `/v1`); `AiProvider.None` registers a client that refuses every call and the availability check says AI is off.
- **Jobs** (`iTerminal.Core/Jobs/`): Periodic refreshers feeding status-bar and dialog models — `DriveInfoJob`, `NetworkInfoJob`, `FolderIndexJob`, `MusicLibraryIndexJob`, `DocumentLibraryIndexJob`, `OnlineQuoteJob`, `WeatherJob`, `RuntimeDependencyCheckJob`, `OllamaServerJob`, plus `SettingsSynchronizationJob` and `MemoryDriveSynchronizationJob` which flush in-memory state to SQLite. A job must not make a blocking call on its own thread that cannot be cancelled — the host gives shutdown five seconds, and `DriveInfoJob` asking `DriveInfo.IsReady` there (seconds on a card reader or a sleeping disk) held every F10 Quit for all five; such calls go on a task the job waits for cancellably.
- **Dialogs** (`iTerminal.Core/Dialogs/`, commands in `iTerminal.Core/Commands/`): The app's modal features (Git client, solution viewer, calculator, unit converter, process/task/disk/network/theme/settings managers, file operations, etc.). Each is a `Dialog` registered as transient in DI and opened by a `ShowDialogCommand<TDialog>` subclass that declares its `Key`, `Title`, `Description`, and optional `OnBeforeShow`/`CanExecute`. Notable keys: Shift+F1 command palette, F2 terminal, Shift+F2 compare folders, F3 view (opens `SolutionViewerDialog` on `.slnx`/`.sln` and `MusicFileViewerDialog` on a local audio file), Shift+F3 open with, Ctrl+F3 quick view, F4 edit, Ctrl+F4 edit with, F5 copy (Insert / Shift+↑↓ / Num+ Num- Num* mark rows first to copy several), Alt+F5 compress, Shift+F5 extract, F7 find files, Shift+F7 create folder, F8 delete, Ctrl+L create link, Shift+F11 sort, Shift+F12 checksums, Ctrl+F12 properties, Ctrl+F6 git history drive, Ctrl+F8 recycle drive, Ctrl+F9 Docker drive (on a container row: Shift+F9 start/stop, Ctrl+Shift+F9 restart), Ctrl+G Git client, Ctrl+N network browser, Alt+F11 iPhone browser, Ctrl+A calculator, Ctrl+E unit converter, Alt+F3 document manager, Alt+F8 package manager, Ctrl+O interactive shell (Ctrl+Shift+O the full-screen command log), Ctrl+C / Ctrl+X / Ctrl+V file clipboard (Ctrl+Shift+X the password manager), Alt+F9 disk manager (E eject, F format, M disk image), Ctrl+Shift+F11 mount the image under the cursor, Ctrl+F2 AI model details (Ctrl+B swaps the AI bar for the terminal bar). The Tools menu lists them all; `MenuShortcutTest` checks every menu label against the key its command is bound to. The music player is *not* a dialog — Ctrl+F7 (or Ctrl+Shift+M) points the two panels at the music drives instead (see below).
- **Content lenses** (`iTerminal.Core/Controls/Lenses/`): `IContentLens` decorates the entry list without the browser knowing why — `GetHeaderIndicator` + `DecorateRow`. `GitLens` colours rows by git status. Registered as `IContentLens` singletons and applied by `ContentBrowser`.

### Drives and URL schemes
A panel's drive kind is derived from the URL scheme (`iConsole/Data/Container.cs` → `Url.ContainerType`), and `ContentModelService.AddContentModel` maps it to a model:

| Scheme | Content model | Backing service |
| --- | --- | --- |
| `file://` | `ContentModelFileSystem` | `IFileSystemService` |
| `zip://`, `gz://`, `targz://` | `ContentModelFileSystemArchive` | `IArchiveFileSystemService` |
| `ssh://user@host:/path` | `ContentModelSshDrive` | `ISshFileSystemService` |
| `smb://[user@]host/share/path` | `ContentModelSmbDrive` | `ISmbFileSystemService` |
| `iphone://<udid>/<afc-path>` | `ContentModelIPhoneDrive` | `IIPhoneFileSystemService` (imobiledevice-net) |
| `memdrive://` | `ContentModelMemoryDrive` | `IMemoryDriveService` |
| `musicplaylist://` | `ContentModelMusicPlaylist` | `IMusicPlayerService` + `IAudioDeviceService` |
| `musiccatalog://` | `ContentModelMusicCatalog` | `IMusicLibraryService` |
| `docker://<container>/<path>` | `ContentModelDockerDrive` | `IDockerDriveService` (docker CLI) |
| `git://<repo>/<revision>/<path>` | `ContentModelGitDrive` | `IGitDriveService` (git CLI) |
| `search://` | `ContentModelSearchResults` | `IFileSearchService` (rows are `file://`) |
| `preview://` | `ContentModelPreview` | `IFilePreviewService` |
| `archive://<archive>/<path>` | `ContentModelArchiveDrive` | `IArchiveDriveService` (SharpZipLib; 7-Zip CLI) |
| `recycle://<name>` | `ContentModelRecycleDrive` | `IRecycleBinService` over an `IRecycleBinStore` |
| `dav://`, `davs://` `[user@]host[:port]/path` | `ContentModelWebDavDrive` | `IWebDavFileSystemService` (HttpClient + PROPFIND) |
| `mtp://<device>/<storage>/<path>` | `ContentModelMtpDrive` | `IMtpDriveService` over an `IMtpBackend` (`gio` / the Windows shell) |

When adding a scheme, all four pieces must line up — and if its file system is a shared service rather than one its panel hands over (`IFileSystemProvider`), add it to `FileSystemResolver`, which every file operation resolves through: the constant in `Container`, the parsing branch in `Url`, the `ContainerType` case in `ContentModelService.AddContentModel`, and the DI registration of the file-system service. Add it to `FolderUrlValidationModel.SupportedSchemes` too (`FolderUrlValidationModelTest` holds the list to `Container`), and to the Places page if a user should be able to pick it.

### The tool-backed drives, F7 search and quick view (`docker://`, `git://`, `search://`, `preview://`)
Ctrl+F9 points the focused panel at `docker://`, Ctrl+F6 at the git history of the repository it is in, F7 opens `FindFilesDialog`, and Ctrl+F3 turns the *other* panel into a preview of the entry under the cursor. Each of the drive keys toggles: pressed on its own drive it takes the panel back. F7 used to be Create Folder, which is now **Shift+F7**.

- **`ContentModelAsyncDrive` is the base of the first three**, because their listing comes from a process or a walk that cannot fit the 200 ms key-handler budget. `SetUrl` puts the `..` row up at once and lists on a background task; a result is written only if its generation and URL are still current (the same stale-result rule as `FilePanelRefreshTask`); a failure goes in the footer and keeps the `..` row. `ExistsFile`/`ExistsFolder` answer **from the listing** — they gate F3/F5/F8 on the key handler, and asking the tool would spawn a process there. `ListingTask` is the test seam.
- **The way out of a drive's root is the folder the panel came from.** `ContentModelService.SetUrlAsync` records it (`ContentModelAsyncDrive.RememberReturnUrl`, settings key `<panel>.ReturnUrl`) on *every* crossing into one of these drives — hot key, Places page, typed URL — and only from outside them, so docker → search still leads back to the disk. The root's `..` and the toggle keys both go there.
- **Copy/move/delete reach these drives through their panel.** `TransferCommand`/`DeleteCommand` resolve a file system by scheme; for these drives they fall back to the panel's `IFileSystemProvider.FileSystem` (the shared service). A cross-drive folder copy walks the source with `IFolderListingFileSystem.ListChildren`, which `ContentModelFolderTaskHelper` uses for any drive it has no case for.
- **`git://` escapes the repository and the revision, and nothing else.** The repository is a local path (`C:\src\app`) and a branch name routinely holds a slash (`feature/login`); the tree path stays raw so `Url.Name` — what a copy names its target — is the real file name. `GitDriveUrl` builds and parses. Levels: remembered repositories (setting `GitDriveRepositories`) → HEAD, branches, tags, remotes and the last 100 commits → the revision's tree (`ls-tree -z -l <rev>:<path>`). File contents are piped from `git cat-file blob`, so F3, F5 and the preview read an old version without a checkout. Read-only. The repository is found by walking up for `.git` (folder or worktree file), not by `rev-parse`: that runs on the key handler.
- **`docker://` lists with `ls` inside the container and moves bytes with `docker cp`.** `docker exec <c> ls -lAnL -- <path>` is the subset GNU and BusyBox agree on (numeric ids, symlinks followed so `/bin → usr/bin` is a folder); file contents go through `docker cp`'s tar stream, which also works on a stopped container and an image without a shell. The CLI rather than the Engine API, for the reason audio shells out to ffmpeg: it already knows how to reach the daemon. A daemon that is not running is reported in words, not as a named-pipe paragraph.
- **A container is operated from its row, and is never a folder to a file operation.** On the container list, Shift+F9 starts or stops the container under the cursor (by `DockerContainerEntry.IsRunning`) and Ctrl+Shift+F9 restarts it (`Commands/Docker/`, gated like the music commands: the focused model must be a docker panel *and* this browser's own). `ContentModelDockerDrive.RunContainerAction` runs `docker start|stop|restart` on a background task (`docker stop` alone waits ten seconds), says it in the footer, re-lists, and writes the outcome *after* the listing lands — a listing clears the footer's message. A container row's URL is the container's root folder and that folder exists, so F8 on it used to offer to delete it with *Recursively delete folder* ticked, and the delete walked the container removing `/etc`, `/usr` and the rest. `DockerContainerEntry` is an `IDriveObjectEntry`, which `FocusedEntry` refuses (cursor row and marks alike), the container list cannot be marked, and the service itself refuses to delete, move or read a container's root.
- **The quick view of a container is its log**: `IEntryPreviewSource` lets a panel answer for its own rows before `FilePreviewService` builds a file preview (null means "preview it as a file"). `docker logs --tail 200 --timestamps` replays stdout and stderr on two pipes, so they are merged by the timestamp (fixed-width RFC 3339, which sorts as text) and the stamps and colour codes dropped (`DockerDriveService.MergeLogs`). `FilePreview.StartAtEnd` opens it on the last line; Ctrl+R in the preview panel reads it again.
- **Ctrl+O opens a real shell inside the container** (`docker exec -it`, see "Lending the terminal"), and **the command log and terminal bar run their commands inside it too.** The terminal runs each command through the focused panel's model (`RunTerminalCommandAsync`), so the docker model runs `docker exec -w <folder> <c> sh -c <command>` — in the panel's folder, or on the container list in `/` of the container under the cursor — and the prompt says where (`ITerminalPromptSource`: `web:/etc>`). One command at a time, like the ssh drive, not an interactive shell: the terminal has no TTY to give one, so stdin is closed (a bare `cat` ends rather than hangs), and it goes through the streaming runner, which has no 30-second timeout. A failure that is docker's (no daemon, a stopped container) is said in words; the command's own stderr is shown as written (`DescribeDockerProblem` tells the two apart).
- **`search://` rows are the files themselves** (`file://` URLs, named relative to the search folder), which is what makes F3/F4/F5/F8 work on hits with no code of their own; Enter on a hit opens its folder with the cursor on it. The search belongs to the singleton `FileSearchService`, not to the dialog, so its results outlive it: Ctrl+P in the dialog hands them to the panel (the search keeps running); closing the dialog otherwise stops it. The walk (`FileSearch`) skips reparse-point *folders* (junction loops) but not reparse-point files (OneDrive placeholders), skips `.git`/`.svn`/`.hg`, streams content line by line and treats a NUL in the first 8 KB as binary.
- **`preview://` follows the other panel through `IContentModelService.ModelChanged`** and rebuilds only when the entry or the width changed, after `ContentModelPreview.Debounce`, on a background task. `FilePreviewService` reads at most 64 KB of a text file (hex dump when binary) and hands PDF/Office/HTML/images to F3's own `IFileToTextConverterService`, so the two never disagree. It reads through the panel's `IFileSystem`, so a commit or a container file previews like a local one.

### WebDAV (`dav://`, `davs://`) and MTP phones (`mtp://`)
- **WebDAV, `dav://[user@]host[:port]/path` (HTTP) and `davs://…` (HTTPS)** — `WebDavFileSystemService` over plain `HttpClient` and an XML reader (PROPFIND depth 0/1, GET, PUT, MKCOL, DELETE, MOVE and COPY with `Destination` and `Overwrite`); no package. One client is kept for the run (both panels may be on the same server) and replaced when scheme, host or user changes. The URL holds the raw path and each segment is percent-escaped when a request is built, the server's hrefs unescaped on the way back (`Escape`, `ParseMultiStatus` — `internal` for tests). MOVE and COPY are done by the server, so a rename on the drive costs nothing; a copy to another drive streams through `StreamToAsync`/`StreamFromAsync`. A 405 from MKCOL ("already there") and a 412 from a no-overwrite MOVE/COPY are not errors; a 401 says a login is needed. The password comes from a saved `NetworkProtocol.WebDav` profile (host + user) in the vault, never from the URL — as for FTP, **there is no dialog yet that creates such a profile**, so an authenticated server needs one saved by other means. Digest/NTLM are whatever `HttpClientHandler` negotiates; HTTPS certificates are validated normally.
- **MTP, `mtp://<device>/<storage>/<path>`** — the root lists devices, a device lists its storages, below that are folders (`MtpDriveService`, a `ContentModelAsyncDrive` like docker: listing off the key handler, `IFileSystemProvider`). Devices and storages are `IDriveObjectEntry` rows and the service refuses to delete or write to them. There is **no MTP library**: a phone only talks MTP to the operating system's own driver stack, so `IMtpBackend` is the seam — `GioMtpBackend` on Linux (GVfs through the `gio` CLI: `gio mount -li`, `list -l`, `cat`, `save`, `mkdir`, `remove`; the device must be unlocked, on *File transfer* and mounted) and `ShellMtpBackend` on Windows (the This PC shell namespace through PowerShell's `Shell.Application`, names passed as single-quoted literals; files move through a temp folder because the shell copies files, not streams). The WPD NuGet wrappers need a `-windows` target framework, which would end the app's plain `net10.0` build.
- **MTP has no rename or universal server-side copy**: a copy within a device is download + upload, a move of a file is that + delete, a folder move is refused (copy it, then delete it).
- **Honest limits:** both MTP backends were written against documented tool output and are tested against recorded output and a fake backend (`MtpTest`) — **neither has been run against a real phone**. On Windows deleting is refused on purpose (the shell's delete asks for confirmation in a window a terminal cannot answer); delete in Explorer. The end-to-end suite registers an `UnavailableMtpBackend` so no run asks the machine for its phones.

### mc-style additions: hex view, user menu, folder size, FTP
- **F3 viewer hex mode.** `FileViewerDialog` owns a `HexViewer` beside the text control; **F4 toggles** between them (title says `[HEX]`). The bytes are read lazily on the first toggle through the panel's `IFileSystem.ReadFileAsync`, so any drive's file can be dumped, and the text view is never given up (ToggleHexModeAsync flips visibility and focus — `ShowAsync` re-hides the dump, since it makes every child visible). **F5 in the dump goes to an offset** (`GoToOffsetDialog`): a decimal number, `0x…` or `…h` in hex; past the end goes to the last byte. `HexViewer.ShowOffset` puts the row a third of the way down.
- **User menu, Shift+F10** (`UserMenuDialog`, `UserMenuService`). mc's F2 menu; F2 is the terminal here, so it sits with the other Shift+F-keys. The menu is a text file, `usermenu.txt`, in the data folder, written with defaults on first use and read on every open (no cache, so editing it takes effect at once; F4 in the dialog opens it with the system default). Format: `<key> <title>` in the first column, indented command lines, `+ f <patterns>` before an entry to limit it to matching names, `#` comments. Macros (`UserMenuMacros`): `%f %b %x %d %D %s %t %%`, names quoted for the shell the script runs in. An entry is written to a temp script and run on the lent terminal (`IInteractiveShellService`, banner off) with a "press a key" pause, then every panel is re-read. Local folders only (`CanExecute`).
- **Ctrl+Space folder size** (`CalculateFolderSizeCommand`). Measures the folder under the cursor, or every marked folder, with `IFilePropertiesService.MeasureAsync` on a background task and writes the total into the row's `FileSize` (`…` while running). The figure lives on the row, so a refresh of the folder rebuilds the rows and drops it, as in mc. Local disk only, never `..`.
- **FTP drive, `ftp://[user@]host[:port]/path`** (`FtpFileSystemService` over FluentFTP, `ContentModelFtpDrive`). A singleton service holds one control connection, serialised by a lock — both panels may be on the same server — and reconnects when the host or user differs. No user means anonymous. A password comes from a saved `NetworkProtocol.Ftp` profile in the vault, never from the URL (the URL has no password part). FTP has no server-side copy, so a copy within the drive goes through memory; folder copy/delete walk through `IFolderListingFileSystem`. `Url.Host` holds `host:port`; `FtpFileSystemService.SplitHost` splits it. The path part of the URL takes anything after the first `/`, spaces included.

### Archives as folders (`archive://`)
Enter on a ZIP, TAR, TAR.GZ or TAR.BZ2 — and, with 7-Zip installed, 7z, RAR, ISO or CAB — opens it as the `archive://` drive (`NavigateToArchiveCommand` → `SetUrlAsync`, so the way back is recorded): real folders, F3/Ctrl+F3 on entries, F5 to copy files and folders out, read-only otherwise. It is a `ContentModelAsyncDrive` like docker/git, so listing never runs on the key handler; `IsDriveRoot` is overridden because the archive's top level, not the bare scheme, is where `..` leaves it — back to the folder the archive is in, **with the cursor on the archive** (`ContentModelService.LandOnTheArchiveLeft`).

- The archive's local path is one percent-escaped segment (`ArchiveDriveUrl`), as git escapes its repository; the inner path is left raw so `Url.Name` is the entry's name.
- **An archive's listing is read once and cached, keyed by size and write time** (`ArchiveDriveService.GetIndexAsync`): every folder is drawn from it, and a TAR.GZ cannot be listed without decompressing all of it. Folders an archive only implies (most ZIPs store `a/b/c.txt` and no `a/`) are added (`WithImpliedFolders`). A TAR entry is read by scanning to it; a ZIP entry by seeking; a 7-Zip entry with `7z x -so`.
- 7-Zip is always given a closed stdin: an archive with encrypted names makes it ask for a password, and inheriting the app's console it would wait there for good. Encrypted content is pointed at Shift+F5.
- The old `zip://…@/` drive (`ContentModelFileSystemArchive`) is still there for typed URLs; Enter no longer leads to it.

### The recycle drive (`recycle://`, Ctrl+F8)
Ctrl+F8 — beside F8, which fills it — points the focused panel at the recycle bin: one flat list of what was deleted, newest first, each row dated by *when it was deleted* and the info strip saying where from. **Enter restores** the row under the cursor or the marked rows to where they were deleted from; **F8 deletes for good**, through the ordinary Delete dialog; F3, quick view and F5 read a deleted file where it lies. Pressed again, Ctrl+F8 goes back. It is a `ContentModelAsyncDrive`, so listing never runs on the key handler.

- **The bin is read from the files it is made of, not through the shell** (`IRecycleBinStore`). On Windows every volume keeps `\$Recycle.Bin\<SID>`, where a deleted file is a pair: `$R<random>.ext`, the file, and `$I<random>.ext`, a record of its original path, size and deletion time (`WindowsRecycleBinStore.ParseRecord`: version 1 is a fixed 260-character path field, version 2 a length and that many characters). Restoring is moving the `$R` file back — always within one volume, so a rename — and removing the record. The shell's COM route restores by invoking a verb whose name is translated with the system's language; the file format has been stable since Vista, and makes the store something a test can build in a temporary folder. On Linux it is the freedesktop trash (`~/.local/share/Trash/files` + `info/*.trashinfo`), the home trash only. macOS keeps no record of where a file in the Trash came from, so the drive says so instead of listing.
- **A row's URL is its name** (`recycle://report.pdf`), not an id: copying a row out then names the copy correctly, and `Url.ParentUrl` is `recycle://`, which is what `PanelRefreshHelper` matches a panel by after a delete. Two deleted files can share a name, so the second is listed as `report (2).pdf` — numbered oldest first, by the store's key on a tie (`RecycleBinService.Name`), so a row's URL does not move between listings. The service keeps the name→item map of the last listing.
- **A deleted folder is one row, and a file to every operation** (no trailing slash). Restore and delete-for-good take the whole folder, the only thing either can mean here; it cannot be entered or copied out. Were it a folder URL, F8 would send the delete discovery walking into it.
- **Restore asks nothing and never overwrites.** It is undone by deleting the file again, so a y/n would be noise; and when something has taken the deleted file's place it is reported ("already exists there") and both are left alone — what is there now is the newer of the two. The folder it was in is recreated if that was deleted too. The outcome is written to the footer *after* the re-listing lands, as on the docker drive (a listing clears the status).
- **Emptying the bin is Mark All, then F8** — the Delete dialog is the confirmation, and there is no separate "empty" key to press by accident. On this drive the dialog's recycle box is off: `RecycleBinService.DeleteFile` purges whatever the flag says.
- **`RestoreRecycledCommand` (Enter) reads the focused model and nothing of its own**, so both panels' instances answer alike, and declines on the `..` row, where Enter still leaves the drive.
- **The end-to-end suite registers a store rooted in the sandbox** (`TerminalApp.RecycleBinFolder`, in the Windows format on every system; `PutInRecycleBin` seeds it). The drive restores and deletes for good: **no test may reach the real bin through the app**, and `RecycleBinTest` builds its bins under a temp folder for the same reason.
- **On Linux F8 puts the file in the freedesktop Trash** (`FreedesktopTrash`, `ITrashService`; the Delete dialog's box reads *Move to Trash*), in the form `FreedesktopTrashStore` and every Linux file manager read: `files/<name>` plus `info/<name>.trashinfo` (`Path=` percent-encoded, `DeletionDate=` local time). A file on the same volume as `$XDG_DATA_HOME/Trash` goes there with its absolute path; one on another mount goes to `<mount>/.Trash-<uid>` with a path *relative to the mount point*, because moving it to the home trash would be a copy across volumes — a slow delete that can fail half-done. Volumes come from `/proc/self/mountinfo` (longest mount point that contains the path; octal escapes such as ` ` are decoded). The name is reserved by creating its `.trashinfo` with `FileMode.CreateNew` before the file moves (`name`, `name.2`, …), so two programs trashing `a.txt` do not collide, and a failed move removes the record again. A file already inside a trash is deleted for good (nowhere further to move it); a volume where no trash can be made throws in words rather than silently deleting. The store lists the home trash *and* the existing `.Trash-<uid>` / `.Trash/<uid>` folders. `directorysizes` is not maintained (readers rebuild it). The end-to-end suite registers a `FreedesktopTrash` rooted in the sandbox with no per-volume trashes: **no test may put a file in the real Trash.**
- Not built: browsing inside a deleted folder, and the `$topdir/.Trash` (sticky-bit) variant of a per-volume trash — `.Trash-<uid>` is the form the specification allows when it is absent.

**The info strip follows a panel's model across a change of drive kind** (`ItemInformation.FollowModelSwap`). A navigation that crosses drive kinds replaces the panel's model with a new instance, and nothing handed that instance to the strip: it went on describing the old model's cursor row — "Up to: …" for the folder the panel had left — for as long as the panel stayed on docker, git, an archive or the search results. It now asks the service for the model registered under its panel's name whenever `ModelChanged` fires.

### Cloud drives, disk usage and elevation (`Services/Cloud/`, `Services/DiskUsage/`, `Services/Elevation/`)
- **`s3://[accessKeyId@]bucket/key`, `onedrive://[account]/path`, `gdrive://[account]/path`** are `ContentModelAsyncDrive`s over `HttpFileSystemServiceBase` (signing/retry/spooled uploads); listing and sign-in never run on a key handler. S3 is hand-signed (`AwsSignatureV4`, checked against AWS's worked examples), path-style on custom endpoints, region learned per bucket from `x-amz-bucket-region`; credentials come from a password-manager entry titled `S3…` (user name = access key id, password = secret, notes `endpoint=`/`region=`/`token=`), else `AWS_*` env, else unsigned (public buckets).
- **OneDrive (Graph) and Google Drive use the OAuth device flow** (`OAuthTokenProvider`): no client id is shipped, so set `Cloud:OneDrive:ClientId` / `Cloud:GoogleDrive:ClientId`+`ClientSecret` in `appSettings.json`. The first listing starts the grant, posts the code as a persistent notification and throws `CloudSignInRequiredException` (shown in the footer); Ctrl+R after approving. Refresh tokens live in the password manager. Deletes go to the provider's own bin/trash. Drive has no paths: `GoogleDriveFileSystemService` resolves segment by segment with a 60 s cache.
- **Disk usage, Ctrl+Shift+F12** (`DiskUsageDialog`): background walk of a local folder (links not followed), tree kept in memory with the 40 largest files per folder; Enter/←, `g` goes to the panel, `s` sort, `r` rescan.
- **Duplicate finder, Ctrl+Shift+F7** (`DuplicateFinderDialog`, `DuplicateFinderService`): files with identical content under a local folder (the one under the cursor, else the one shown). **Three narrowing stages so most files are never read**: size (a directory listing), then a SHA-256 of the first 4 KB of what shares a size, then a full SHA-256 of what still agrees; a hash match is trusted as equality. Empty files, links, and `.git`/`.svn`/`.hg` internals are not looked at; hard links to one file are listed as copies and deleting one frees nothing. The scan is a `DuplicateScan` on a background task like the disk-usage one (phase and counters readable while it runs; closing cancels it). Groups come largest-waste first with the oldest copy first inside each. Space marks, `a` marks all but the oldest per group (`n`: but the newest), `u` clears, Delete asks y/n then deletes the marked files **to the recycle bin** on a background task and redraws without them (a group left with one copy disappears), `g` takes the panel to the file's folder. **One copy of every group is always kept**: marking the last unmarked copy is refused and the bulk marks leave one standing. The dialog's tests fake `IFileSystemService`: a real delete would fill the machine's recycle bin.
- **Elevation, Ctrl+Shift+A restarts as administrator/root, Ctrl+Shift+R runs the program under the cursor elevated** (`IElevationService`). Windows: `runas`, the new copy gets `--wait-for-parent <pid>` so it opens the data folder only after this one exited. Unix: `sudo -v` on the lent terminal, then `PendingRelaunch` makes `Program.cs` `execvp` `sudo iTerminal` after shutdown; an elevated Unix session uses root's own data folder when sudo resets HOME. The Unix paths and live OneDrive/Google/S3 calls have not been exercised against real services.

### Host identity: SSH known hosts and FTPS (`TrustedHostStore`)
`known_hosts.json` in the data folder remembers what each remote presented, trust on first use (`ITrustedHostStore.Check`: `New` is recorded, `Trusted`, `Changed`). `SshFileSystemService` checks the SSH host key (SHA-256) on the SSH and SCP clients and refuses a changed key with an error naming the host id to forget. `FtpFileSystemService` connects with explicit FTPS first; a certificate that chains to a trusted root is accepted, any other is pinned by SHA-256 the same way. A server with no TLS is used in plain only for anonymous logins or when the `Ftp.AllowPlain` setting is true; otherwise the connect fails with a message saying so. Entries are forgotten by editing or deleting the file (no UI yet); `~/.ssh/known_hosts` is not read.

- **Browsing inside a zip** (`ContentModelFileSystemArchive`): a folder inside the archive lists only its own files and sub-folders (each sub-folder once), not the whole archive. Its ".." row goes up one folder inside the archive, and from the archive's top it leaves for the folder that holds the zip. The row is labelled "..", so `FocusedEntry.IsParentEntry` recognises it and file operations stay off it. An archive that cannot be opened (deleted while shown) leaves the panel with just the ".." row.
- **A folder that has gone** (`ContentModelFileSystem.SetUrl`): the panel opens its nearest parent that still exists, so a removed drive or a deleted folder keeps the user near where they were. The working directory is used only when nothing above it exists.
- **Folder size count in a panel** (`FileInformationRefreshTask`): progress is delivered through `Progress<T>`, which posts each report to a later turn, so a report can arrive after the final count. The count is therefore marked finished under a lock before the final value is written, and a late report is ignored; otherwise the row kept "N…" for good.
- **Opening a zip** (`ContentModelFileSystemArchive.Refresh`): the ".." row is shown at once and the archive is read on a background task, which lands its listing only if the panel still shows that location. The key handler never waits for the read.
- **S3 credentials and region** (`S3CredentialResolver`): the password manager first, then the standard `AWS_*` environment, then the `Cloud:S3` configuration. Configuration fills only what the two above did not give; an unsigned request is the last resort.
- **Cached quotes** (`CacheService`, `InstrumentQuoteHelper`): each quote is judged on its own age, and a quote's history is bounded (the newest 100 values).
